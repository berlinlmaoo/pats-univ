The poster step uses server `optional`, `state`, `completion`, `outcome`, `rewardXp` and `proof`. It never becomes the required current step and never prevents reservation, check-in or later journey steps. Skipping records the tap; it does not award XP. Sharing opens Android's chooser. A member then submits a screenshot as JPG, PNG or WebP up to 5 MiB. The native picker clears a previous selection before validating its replacement, bounds file reads, and checks type, size and image decoding before upload. Journey actions share a mutation guard while a write is running.

Pending and rejected proofs can be replaced; approval disables replacement. Rejected proof copy includes the crew's reason. Approval credits the configured reward once through the server XP ledger; the default and tested value is +2 XP. The client displays server-awarded XP and does not credit a local balance. The server retains one proof per member/event and rejects a repeated decision or replacement after approval. Approved proof notifications retain the event/proof context and View proof action.

The event report requires every field, including zero where appropriate:

| Field | Meaning | System reference beside the input |
|---|---|---|
| `tablesSold` | Tables sold | Confirmed table reservations |
| `sofasSold` | Sofas sold | Confirmed sofa reservations |
| `fdcSold` | FDC sold; First Drink Charge / Free Drink Coupon | No separate reference supplied |
| `paxTotal` | Total guests | `reservationPax` |
| `membersAttended` | Members attended | Recorded event check-ins |
| `nonMembersAttended` | Non-members attended | No separate reference supplied |
| `newMembers` | New members registered | Registrations in the event's reporting window |

Each value must be an integer in `0…1,000,000`; blank, negative, fractional, oversized and nonnumeric values are invalid. Reference values are hints and never fill or overwrite admin entries. Incoming refreshes preserve an unsaved draft. Saves use one report per event and show the server's named editor, timestamp and newest-first changes with before/after values. Regional permission is limited to the event city; HQ can edit across cities. The API remains authoritative for `canEdit` and scope.

FDC `{ value: 0, status: "reported" }` displays **0**. `{ value: null, status: "notReported" }` displays the unfilled state. A zero report therefore clears Reports due and is never mistaken for a missing report. The obsolete HQ-definition and poster-coming-soon strings are removed from native dictionaries; sync strips superseded shared compatibility labels so they cannot return in a later build.

The report overview submits applied date filters in `YYYY-MM-DD` form, validates calendar dates and start/end order, and exports the applied full-dashboard query as CSV. Regional city scope is enforced on the server; HQ additionally has an All cities/city filter. Event and edit timestamps use event-city timezone context; raw ISO UTC remains visible while historical city context is unavailable. The default Reports due view matches unreported events ended within the last 30 days; changing its period filters unreported events by end date in the event city's zone. CSV export belongs to the full report dashboard.

## Private media and credentials

`Api.posterProofImage` accepts only `/api/poster-proofs/<id>/image` with the optional numeric version query generated by the server. It attaches bearer credentials to that exact route on the configured API origin. Redirect following remains disabled. Generic signed-media downloads remain credential-free, including third-party storage origins. A response image URL cannot select an arbitrary authenticated origin or route.

Member and crew proof views use this authenticated route and key displayed images by signed-in user and URL. The server permits the owner, authorized same-city crew and HQ, and rejects anonymous or other-city access. The multipart proof upload obtains the current access token, retains structured API field errors, and clears a rejected session consistently with other authenticated requests. Review/approval and city authority remain server decisions.
